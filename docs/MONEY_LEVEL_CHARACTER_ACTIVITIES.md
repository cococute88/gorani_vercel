# Money Level character activities

The production Spine JSON files, rather than animation-name guesses, define the poses used here. Gorani has `carry`, `turn_carry`, `pickup`, `throw`, `idle`, `idle_front`, and `run`; Daramji has `idle`, `idle_front`, and `run`, but no `carry`. Neither rig has a `walk`, `sit`, or `fishing` animation. Movement already uses `run`. Fishing retains Gorani's existing slow `carry` pose and hand-tracked rod. Daramji uses its own `idle` pose with a smaller rod and separate wrist and angle calibration. Bench sitting uses `idle_front` with a modest vertical squash and bent upper legs for both rigs; no Spine asset was added. The repository's existing art-review handoff notes were checked; there is no separate character-activity prototype file in this checkout.

`CharacterActivityCoordinator` owns one fishing slot and one bench slot. Each character has exactly one activity (`roaming`, `fishing`, `bench-sit`, or `pond-watch`). A replacement takes ownership immediately, removes the old occupant's rod or seated phase, then waits for that character's departure before entering the slot. A displaced fisher walks from the dock toward `pond_edge` and watches the pond. A displaced bench occupant takes 900ms to step to nearby grass at master coordinate (355, 662), rather than rushing back to the distant roaming waypoint. Bench expiration also uses this exit. The logical `bench_exit` anchor stays in safe local idle: it does not add an unverified shortcut through the house or fence to the roaming graph. Invalid drops still use `resolveDrop`'s nearest safe point.

The dock and bench stay baked into the background. `FISHING_SLOT` resolves through the dock-end waypoint, `POND_WATCH_ANCHOR` through pond-edge, and `BENCH_SLOT` uses the 1683 × 935 background's seat coordinate (302, 616). `imagePointToScene` projects that coordinate through the same cover crop as the background. Both targets are reachable at 390px by panning, including while holding a character. No foreground bench mask or art changes are used.

## Mobile camera and gestures

`camera.ts` defines a wide world at the existing cover scale, with a bounded viewport camera. Its X origin uses scaled master-image pixels; the initial X is the previous 51% mobile / 50% desktop crop. Camera bounds are [0, scaled image width − viewport width]. Background images extend to the full world width without changing their assets, scale or initial framing. Houses, statues, labels, ground shadows and activity visuals share `cropX − cameraX` translation. The Spine canvas remains viewport-sized; character placement gets the equivalent camera offset in renderer units, so offscreen characters are not clipped by a translated canvas. The hand observer is converted back to the stable world plane before drawing the rod, tip, line and bobber.

Navigation uses the original crop-relative normalized world plane, including X below 0 / above 100. Pan never changes activity anchors, walkable polygons or exclusion zones. `screenToWorld` undoes client bounds, camera, scale and crop; `worldToScreen` is its inverse. Drag bounds are the image world, not the viewport. No HP/MP UI, header, Back/Settings or footer translates. Rain/wind/sky/lightning remain viewport overlays; pond shimmer/ripples and house practical lighting follow their world surfaces. Weather/SPY tuning is unchanged.

Empty-space swipes resolve intent after 10px with a 1.2 axis ratio and retain that intent until release. `touch-action: pan-y pinch-zoom` preserves native vertical page scroll and pinch zoom. Only horizontal intent captures the pointer and changes camera X. Character hit targets keep `touch-action: none` from pointerdown; changing it only after long press would be too late to prevent browser cancellation. They retain 320ms long press but allow 12px touch slop separately from the existing mouse threshold. A trusted-touch 6px/2px tremor before 320ms reproduced cancellation under the previous 5px threshold; this is a confirmed failure path, not a claim to have diagnosed the user's unconnected Android device.

Active character drag takes precedence over scene pan. It preserves the finger-to-feet offset and listens for movement/release at window scope plus lost-capture cleanup. A 52px edge zone ramps auto-pan to at most 150px/s. The animation loop clamps frame delta and camera X, then recomputes the held world point even if the finger is stationary. Release, cancellation, effect cleanup and hidden-document handling stop/clean up the gesture.

## Verification

- `npm run check:money-level-activities`: A–F ownership replacements, exclusive transitions, actual Spine animations/bones, responsive anchors, rod calibration and invalid-drop safety.
- `npm run check:money-level-layout`: existing graph routes, 16 backgrounds, statue/house geometry and fishing-line projection.
- `npm run check:money-level-mobile`: clamp/no empty edges, intent lock, screen/world inverses, moving-camera drag, safe bench exit, edge speed and Bench/Dock reachability at mobile/tablet/desktop sizes.
- `npm run check:money-level-mobile-browser`: requires an installed Playwright and Chrome, a running **development** server, and optionally `MONEY_LEVEL_QA_URL` (default `http://127.0.0.1:3001`). Supply Playwright via `NODE_PATH` if using bundled dependencies. Screenshots go to OS temp, or `MONEY_LEVEL_QA_OUTPUT`. Do not run Next build concurrently with this dev server: both use `.next`.

Browser tests use Chrome's native input pipeline (`Input.dispatchTouchEvent`) with Android UA, `isTrusted=true`, `pointerType=touch`, actual long-press waits, pointer movement/cancellation, CSS touch-action and native page scrolling—not JavaScript-dispatched mouse-style PointerEvents. The 390px sequence covers A–H, both edge directions, held offset during pan, rod→line→bobber under moving camera, camera bounds/background coverage/no body horizontal overflow and touch cancellation. Tablet touch is checked at 768px; mouse drag, bench/fishing replacements and both fishing rigs are checked at 768px and 1320px. Reduced motion keeps autonomous behavior deterministic while gesture/camera/frame loops remain active. The initial WIP also reported prior 980px desktop QA; that historical report is separate from this run.

No Android device was connected (`adb devices` empty). These results are trusted browser touch emulation, **not physical Android QA**. Production typecheck/lint/build are verified separately. Backgrounds, house positions, statues/assets, dock/bench/pedestal artwork, Weather visual tuning and SPY logic are untouched.
